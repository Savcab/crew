Public webhook ingress

Give local Crew webhook nodes temporary public HTTPS endpoints without exposing the dashboard or installing an application dependency.

01 · Operator path

One foreground command creates the public door

The operator installs the official cloudflared binary once. Crew then owns one temporary tunnel for the selected project and keeps the public origin alive only while the foreground process is healthy.

  1. Start ingress Run crew ingress run. Crew validates MorphDB, takes the project lifetime lock, and starts a hook-only local gateway.
  2. Prove readiness Crew accepts a strict *.trycloudflare.com hostname only after a secret-gated public probe reaches that gateway.
  3. Copy the hook URL In another shell, crew webhook show <name> returns the live HTTPS origin plus the node’s existing secret capability path.
  4. Stop cleanly Control-C removes active state, closes the gateway, and terminates the exact tunnel child. The temporary public URL goes offline.
Temporary by design. A restarted Quick Tunnel gets a new public hostname. External webhook providers must be updated after every new ingress run.
02 · Data path

The tunnel cannot reach Crew’s control plane

There is one tunnel per running Crew project, not one per webhook. It targets a fresh private Unix socket served by a purpose-built gateway that recognizes only secret hook POSTs.

No general reverse proxy The public child points at a server with no dashboard, API, asset, or terminal routes.
No hidden daemon The URL lives with crew ingress run; parent-pipe EOF also stops the child after hard owner death.
No package stack Crew supervises the separately installed official binary using only the Python standard library.
03 · Contract

Small CLI surface, explicit ownership

run is human-only and foreground. status is read-only. webhook show prefers the current live origin and otherwise falls back to the configured base or relative hook path.

Commands

  • crew ingress run
  • crew ingress status
  • crew webhook show <name>

If cloudflared is absent, run exits with an installation hint before starting the gateway or publishing state. Crew never downloads or updates the binary.

Lease and live state

  • An owner-only JSON state file is scoped by canonical MorphDB origin and app.
  • Its adjacent lock is held for the full foreground lifetime; readers ignore state unless that lock is contended.
  • State holds only public origin and lifecycle metadata—never a capability, full hook URL, or local gateway endpoint.
  • Each lease gets a unique private Unix socket and a unique owner-only Cloudflare config, both removed on orderly shutdown and never reused.
Lifecycle mechanics

A new owner clears stale state while holding a shared lock before upgrading to the exclusive lifetime lock, preventing predecessor state from being attributed to a takeover process. The per-run config pins the private unix:/… service, disables origin chunking, and prevents discovery or mutation of the user’s Cloudflare configuration.

cloudflared starts with no auto-update, info-level JSON logs, and Quick Tunnel mode. A standard-library watchdog owns that exact process and listens on a non-inherited parent-lifetime pipe. Owner exit—including SIGKILL—closes the pipe, after which the watchdog terminates and reaps its child.

04 · Trust boundary

Reject ambiguity before allocating the body

The gateway has a deliberately narrow parser and generic responses. It preserves only the provider fields needed by existing webhook templates and delivery.

Admission and redaction

  • Accept only raw POST /hooks/<43 URL-safe characters>.
  • Reject query strings, percent escapes, trailing slashes, absolute targets, transfer encoding, ambiguous lengths, oversized or slow bodies, and Expect.
  • Resolve the capability before body allocation, then revalidate inside webhooks.receive before durable delivery.
  • Strip hop-by-hop and forwarding identity headers. Preserve signature and idempotency headers for templates and receipts.
  • Cap admission before thread creation and apply absolute header/body deadlines.

Process authority and privacy

  • The child receives a minimal allowlisted environment with no Crew, MorphDB, Cloudflare, agent, provider, or model credentials.
  • Parser failures and responses reveal no targets, headers, traces, local paths, or versions.
  • The dashboard remains loopback-only and is never used as the tunnel origin.
  • Cloudflare terminates public HTTPS for a Quick Tunnel and can therefore process webhook plaintext. End-to-end provider privacy is outside this feature’s promise.

Failure behavior

Failure Safe result Recovery
cloudflared missing No gateway or live state is published. Install the official binary and retry.
Backend or schema unavailable Ingress exits before public exposure. Restore MorphDB and retry.
Readiness fails No origin is trusted; child and gateway stop. Check outbound connectivity and start a new run.
Gateway or tunnel dies Active state is removed and the surviving side stops. Restart ingress and update the external provider with the new URL.
Second project run The second owner refuses without touching the live process. Inspect status or stop the foreground owner.
Hard owner death The OS releases the lock; readers ignore stale JSON; the watchdog reaps its exact child. Start a new lease, which gets fresh config and socket paths.
05 · Delivery

Additive rollout with a direct reversal

The feature requires no database migration and does not change webhook node, edge, receipt, or message formats.

Delivery slice

Expose hooks through a lean public gateway — delivered in this feature’s record-creating commit.

  • Add the hook-only gateway, project lifetime lock, foreground tunnel lifecycle, retained-child watchdog, live state, CLI, and verification.
  • Build directly on the verified webhook-nodes and foreman-webhook-control dependencies.
  • Keep all durable delivery behavior in the already-established webhook path.

Reversal

Remove the ingress command and supporting ingress components. URL generation then returns to configured-base or relative-path behavior; existing data remains untouched.

Explicit non-goals

Stable domains, an SLA, multiple providers, a daemon, automatic binary installation, arbitrary port forwarding, and public dashboard access.
