Harness goal badges

Badge every graph node whose agent currently has an open goal, so the crew's standing work is visible without opening a terminal.

User flow

Start state

crew harness can already answer "who is pursuing a goal?" — but only if the operator thinks to ask, one command at a time. The graph is where a standing crew is actually watched, and it showed only liveness and whatever an agent chose to publish. The goals agents were actually working toward were invisible there.

Outcome

Each card carries what its harness knows: ◎ rebuild the search index +2. One glance separates the agents pursuing something from the idle ones; the hover gives the full reading, and +N counts the other open goals. A node with no badge is genuinely quiet; a node whose harness Crew cannot read is muted instead, never blank.

Architecture

Public interface

Commands and APIs

  • GET /api/graph/snapshot — each agent row gains a harness object: supported, goal, goal_count.
  • Webhook nodes are never probed and never carry the field: a webhook runs no harness.
  • The field is additive. A client that ignores it renders exactly as before.

Data and lifecycle

  • Nothing is stored: no schema change, no new field on the agent row, no migration. Each poll re-derives the reading.
  • One badge, one count. When several goals are open the first is shown and the rest are counted (◎ first of several +3).
  • Badges follow the poll: a finished goal's badge disappears on the next snapshot.

Security and failure boundaries

Authority

  • The snapshot is already operator-capability gated; this adds no route, no parameter, and no new authority.
  • Goal text is operator content read from a file Crew does not control, so it is escaped at render — never interpolated as markup — and clipped for the pill, with the full reading in the title and the accessible name.
  • The probe's reason is deliberately withheld from the browser: the UI's question is "readable or not", and the diagnostic string can contain a local path.

Failure behavior

  • The probe pass is wrapped: any exception costs the poll its readings and nothing else. Cards simply render unbadged.
  • A runtime Crew cannot read is muted (.harness-unknown), not silently unbadged — "no goal" and "no reading" must not look the same.
  • One probe pass serves the whole snapshot, because readers may shell out to ps; the poll cost does not scale with crew size.

Rollout and reversal

Additive and stacked on harness-introspection, which contributes the reading itself. Nothing persists, so reversal is dropping the _enrich_harness call and the badge markup and rebuilding the bundle; existing cards return to their previous shape on the next poll. Operators who never look at the graph are unaffected — crew harness keeps working on its own.

Engineering inventory and redaction notes

Declared code: crew/server/app.py (_enrich_harness and the guarded probe pass), frontend/src/graphEngine.js and frontend/src/app.css (the badge), the rebuilt static/ bundle, and README.md. Declared tests: tests/test_harness_snapshot.py for the projection and its failure behavior, frontend/tests/harness_badges.test.js for the card contract, tests/browser/harness-badges.md for the procedure executed against the running dashboard, and one integration case in tests/test_dashboard_api.py that asserts the reading over real HTTP from an isolated dashboard process.

The browser pass earned its place: the badges first shipped inside the card's flex name row, where jsdom — which performs no layout — reported them present and correct while a real browser squeezed each pill down to its glyph and dropped the text entirely. The fix moved them to their own row, and a structural test now asserts no badge renders inside .nm, so the same mistake fails in CI rather than only in a screenshot.

Evidence was captured against a throwaway fixture agent on the hermes runtime whose goal was a real card created on the live Hermes kanban for the capture; the fixture agent and the card were both removed afterwards, and the visible goal text is this feature's own work, not private operator content.
