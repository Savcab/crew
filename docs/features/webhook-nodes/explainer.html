Crew feature · local ingress primitive

One POST.
Many durable messages.

A webhook becomes a source node on the Crew graph. Its payload is rendered once, then every outgoing edge independently authorizes and stores a message for its agent.

Boundary: this feature serves hooks on Crew's loopback dashboard. It does not start a tunnel or expose the dashboard to the Internet.

Control and delivery stay separate

  1. The operator configures topology through authenticated controls.
  2. The caller's secret URL authorizes only one hook invocation.
  3. Crew parses once and freezes the outgoing edge set.
  4. Each edge independently accepts or rejects a durable message.
Safe by construction Credential headers never enter templates. Unknown capabilities are rejected before body read. Public failures cannot leak private backend diagnostics.
Provider retry friendly Recognized delivery IDs are hashed. The receipt freezes message text and exact route identities; stable per-edge request IDs prevent duplicates without redirecting an old payload.
Uses Crew's mail gate Existing edge identity checks, budgets, transforms, provenance, and FIFO delivery apply without a second messaging system.
Deliberately local CREW_WEBHOOK_PUBLIC_BASE_URL changes display only. Managed Internet access belongs to the stacked public-ingress feature.
